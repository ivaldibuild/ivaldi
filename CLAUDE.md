## Current state of the repository

The repo is an early scaffold. Most of the layout is reserved but empty, so don't assume code exists because a directory does:

- Three binaries ([ADR 0010](docs/adr/0010-one-binary-for-the-components.md), [ADR 0013](docs/adr/0013-one-agent-per-runtime.md)): `apps/control-plane` builds `ivaldi`, whose subcommands `serve`, `gateway`, `worker`, and `indexer` start each component (only `serve` does anything yet: it validates the config, opens the database, runs IAM bootstrap, and serves the API and the authorization server; `cmd/server/wire.go` is the composition root); `apps/cli` builds `ivaldictl` (`auth login`/`status`/`logout`: browser sign-in as the `ivaldictl` OAuth client with a loopback redirect and PKCE, sessions kept in `credentials.json` and refreshed; or a service account's API token from `--api-token`/`IVALDI_API_TOKEN`, the only way in CI, where it never opens a browser; `release create`/`publish`/`withdraw`/`get`/`list`, reading the commit, ref, and run from GitHub Actions or GitLab CI; `service-account create`/`list`/`get`/`suspend`/`reactivate` (alias `sa`) and `api-token create`/`list`/`revoke`, whose `create` prints the secret once; `change record`, which records a Change for the CI commit (or `--commit`s) with its Work Item, Session, and pull request; commands take an `app.App` so tests inject the environment, clock, HTTP, and store; see `docs/self-hosting/ci-releases.md`); `apps/k8s-agent` builds `ivaldi-k8s-agent`, the Kubernetes agent (design: `docs/design/k8s-agent.md`; plan: `plans/issue-52-clusters-and-k8s-agent.md`, Phase B). Domain objects are the only surface that mutates domain state: their fields are unexported, they are created with `New…` constructors that apply creation rules, and they change only through their methods (`Update`, `Archive`, `MakeDefault`, `TransferTo`, `Change`, …). No method takes a time: domain objects and audit records read `pkg/clock`, which returns UTC truncated to microseconds so objects compare equal after a database round trip; tests fix it with `clock.Fix(t, …)` and so must not run in parallel. A domain type that declares `Prefix()` (such as `Workspace` → `wsp`) gets prefixed IDs and registers the prefix with `id.MustRegister` in its package's `init` (a prefix claimed twice panics at startup); a type without `Prefix()` gets a plain ULID. GORM entities have no ID hooks. Database access goes through `pkg/database` (see Shared packages).
- The conventions every capability now follows, set by `delivery` (new capabilities follow them too):
  - **State and rebuilding** (`workspace` follows this too). Domain types expose `Snapshot()` (not `Data()`). There is no `Reconstitute…`: repositories rebuild stored objects with the same `NewX(props, &id)` constructor, passing the stored ID and timestamps in `NewXProps` (a new object leaves them nil). Creation rules therefore also run on load, so a rule added later must still accept existing rows. Child records owned by an aggregate (Lifecycle phases, Channel rules) are passed in the props and change only through the parent's methods; readers get them as snapshots.
  - **Identity.** Domain types never generate their IDs. Aggregates embed `aggregate.Root` and child records embed `aggregate.Entity` (`pkg/aggregate`), built in the constructor by the capability's `newRoot`/`newEntity(X{}.Prefix(), storedID)`, which generate a new ID or check a stored one and turn a bad one into an invalid-input error. `ID()` comes from the embedded type. `iam` and `workspace` follow this too.
  - **Events** (`iam` and `workspace` follow this too). Domain methods record events with `RecordEvent`, only when something actually changes (`set`/`anyTrue` helpers), and constructors record `<Type>Created` only when `IsNew()`. Types keyed by something other than their own ID embed `aggregate.Events` and count as new when their props carry no stored `CreatedAt`. Events live in `<type>_events.go`: value types named `<Type><PastTense>`, named `<capability>.v1.<aggregate>.<event>`, carrying the typed snapshot after the change plus a `previous_…` field only where a reassignment loses information. Snapshots have snake_case JSON tags and are the events' contract (`TestSnapshotJSONKeys` fixes their keys); hashes and other credential material are tagged `json:"-"`. Usage and contact tracking (agent reports, last-used times) records no event. IAM's shared `principal` methods record `iam.v1.principal.*` events with `PrincipalSnapshot`. Delivery writes its events to the outbox in the same transaction (see ADR 0011); `run` does it after saving and every create does it before the transaction ends. `serve`'s relay publishes them to Redis, where `notifications` consumes them.
  - **Repositories save whole objects.** `UpdateX(ctx, x)` writes what `x.Snapshot()` holds; archive and restore are domain methods the service calls before saving. Every read takes the Organization ID; slug lookups also take their scope and match only active rows. Mappers (`*_mapper.go`, one struct per aggregate) convert between entities and domain types.
  - **Shared helpers.** The clock is `pkg/clock` (`clock.Now()`, `clock.Fix(t, …)` in tests, `clock.CopyTime`), and slugs come from `pkg/slug` (`Create`, `Validate`). Validation errors are `NewErrInvalidInput(msg)`, which matches the `ErrInvalid` sentinel.
  - **Lists page by cursor.** List queries have a `Page pagination.Query` field, and repositories return `*pagination.Result[*T]` (`pkg/pagination`), implemented with `database.Paginate` (see Shared packages). A capability's `postgres` package declares a `database.Keyset` per list and translates `pagination.ErrInvalidQuery` into its own invalid-input error (`delivery/postgres/keysets.go`).
  - **Services.** Each capability declares service interfaces (`EnvironmentService`, …) in `interfaces.go`. Domain types stay in the capability's top-level package; each service interface is implemented by a sub-package (`delivery/environments`, `registries`, `lifecycles`, `applications`) that also holds its HTTP API (`http_api.go`, `http_requests.go`, `http_responses.go`, error mapping in `errors.go`). The sub-package's `New…Service(opts...)` returns its unexported service wrapped in `authorized` (`authorization.go`), which implements the same interface: each method asks the authorizer about the right IAM resource, then passes the decision down with `authorization.WithDecision` (per object ID for batch operations, `""` for the whole call). The service underneath does no authorization; it writes through `internal/change` (`change.Run` for load-apply-save, `Writer.Events`, `Writer.AuditRecord`), whose audit write fails with `change.ErrUnauthorized` when the context carries no decision, so a service wired without its wrapper cannot change anything. Where a service needs one count or lookup from another area's repository, it declares a one-method interface (`LifecycleUsage`, `ChannelUsage`, `TargetLookup`, …) rather than taking the whole repository. `delivery.NewDependents` implements `workspace.Dependent` from the repositories, and `delivery.ActiveWorkspace`/`ActiveProject` check the Workspaces lookup. `delivery/routes_test.go` mounts every controller together to check operation IDs are unique and every operation needs a token.
- `Makefile` wraps golang-migrate's `migrate` CLI (`make help`): `<capability>_migration_generate name=<name>` creates a numbered pair, and `migrate_up`, `migrate_down capability=<c>`, and `migrate_version` take `DATABASE_URL`. Every capability numbers from 000001, so each must use its own version table (`<capability>_schema_migrations`, with `version_control` for `versioncontrol`); the Makefile sets it, so don't call `migrate` against the database without `x-migrations-table`. `ivaldi migrate up|down|version` applies the copies embedded in the binary with the same version tables — that is the path deployments and `docker-compose.yml` use, and CI runs both. `deploy/helm` has charts for `ivaldi` (still close to the `helm create` scaffold) and `ivaldi-agent` (the agent's ServiceAccount, Secrets, RBAC, and Deployment; `values.schema.json` checks every value, and the web app's cluster guide test validates its generated values against it; lint it with `--set controlPlane.url=…`, which is required). `scripts/version.sh <component>` (`ivaldi`, `ivaldi-k8s-agent`, `ivaldictl`) prints that component's SemVer from its own tags (`<component>/vX.Y.Z`), because the components are released independently; the Makefile and CI stamp each artifact with its own, plus the commit and the commit's time. Nothing publishes from a tag push: `.github/workflows/release.yaml` tags, promotes the `:sha-<full>` images CI built on `main`, packages the chart, builds the CLI archives, and opens the GitHub Release (`docs/releases/README.md`). Publishing waits for verification in `ci.yaml`, so a `:sha-` image only exists for a commit whose checks passed. The control plane image also carries the web app it serves (ADR 0016), so there is no `ivaldi-webui` image. `migrations/`, `schemas/`, and `.github/actions/` have no tracked files yet.

make openapi_check   # fails if a committed copy is out of date

`cmd/server`'s `TestTheCommittedOpenAPIIsCurrent` fails while `api/openapi.json` is stale. The description is built from `services.routes` in `cmd/server/routes.go`, the same list `serve` serves, so a new controller is added there (and its service set in the wiring) and never registered elsewhere. ivaldictl generates only the operations listed in `apps/cli/internal/apiclient/oapi-codegen.yaml`; add an operation ID there when a command starts calling it. The web app's `api/models.ts` names generated types rather than declaring its own. Two rules keep the generated types honest: a list in a response is never null (huma's `DefaultArrayNullable` is off, and `api`'s `emptyLists` transformer turns any nil slice into `[]`), and a snapshot field whose Go type has fixed values carries an `enum` tag listing them, pinned to the domain's constants by an `enums_test.go`.

There is no lint config or lint target yet; `go vet` and `gofmt` are the checks.

## Module layout gotchas

- Every app and `pkg/` is a separate Go module. Root `go.work` stitches together `pkg` and every app, including `apps/cli`, so apps import shared code as `github.com/ivaldibuild/ivaldi/pkg/...` without `replace` directives. Builds that run with `GOWORK=off` (for example, a per-module Docker build) lose that and would need a `replace` or a published `pkg` version.
- Module paths: `pkg` is `github.com/ivaldibuild/ivaldi/pkg`, while each app (including the CLI) is its own `github.com/ivaldibuild/ivaldi-<app>` module. `apps/control-plane`'s module, `ivaldi-control-plane`, also holds the gateway, worker, and indexer.
- `VERSION` in each binary's `cmd` package is a `var` so `-ldflags "-X main.VERSION=…"` can set it; the Makefile does.
- `pkg/env` and `pkg/logging` were ported from another project; leftover fixture names (e.g. `dispatch` in `env_test.go`) are test data only.

## Shared packages

- `pkg/env` — struct-tag config loader. Layering is `envDefault` < YAML < environment variables; errors are aggregated (`*env.AggregateError`) rather than returned on first failure. Use `Options.Source` to inject env lookups in tests instead of `os.Setenv`. `LoadDotEnv` loads `.env` files.
- `pkg/logging` — backend-agnostic `Logger` interface with a zap implementation, lumberjack file rotation, and a testify `MockLogger`. Depend on the `Logger` interface, not zap.
- `pkg/database` — opens PostgreSQL with GORM and carries one transaction in the context: `Transactor.WithinTx` starts it (or joins one already in the context), and repositories call `database.Conn(ctx, db)` so their writes join it. A transaction only spans repositories sharing one `*gorm.DB`, so open it once per process. `UniqueViolation`/`ForeignKeyViolation`/`CheckViolation` return the constraint name for translating into domain errors. `TextArray` maps a `TEXT[]` column in a GORM entity. `databasetest.New(t, migrations.FS)` gives tests a throwaway database. Never use GORM `AutoMigrate`; migrations own the schema.
- `pkg/pagination` — `Query` and `Result[T]` for paged lists, with no database code so domain packages and service interfaces can use them (like `pkg/transaction`). `pkg/database`'s `Paginate` implements keyset paging with them: a capability gives it a fresh base query per call and a `Keyset` (the allowlist of sort columns, a default, and the tie-breaking ID column), and gets back a `Page` of rows plus opaque cursors; `ToResult` maps the rows to domain objects. Invalid sorts and cursors fail with `pagination.ErrInvalidQuery` before any query runs.
- `pkg/transaction` — the `Transactor` interface (`WithinTx`) that capabilities depend on to make writes commit together, with no database code, so domain packages can import it. `database.Transactor` implements it. Capabilities use this one rather than declaring their own. The guarantee only holds if every write inside `WithinTx`, including other capabilities' implementations called there, goes through the context it passes.
- `pkg/id` — ULID primary keys, generated through `pkg/aggregate`'s `NewRoot`/`NewEntity`, prefixed for types that declare `Prefix()`. Prefix registration (`id.MustRegister`) catches duplicates only within one program, not across deployables.
- `pkg/events` — `Envelope`, `Wrap`/`Decode`, the handler `Router`, and the `Publisher` and `Consumer` interfaces. `pkg/events/redisstream` implements `Publisher` and `Consumer` over Redis Streams. The publisher writes one flat entry per envelope with approximate `MAXLEN` trimming and wraps every Redis error in `events.ErrUnavailable` (a transport failure, not the event's); the consumer reads with a group, drains its own pending entries on startup, reclaims idle entries from stopped consumers, supports automatic or handler-driven acknowledgement, and dead-letters entries it gives up on (including ones whose handler panics or never finishes). It reads only as many entries as it has free handler slots, acknowledges a finished handler even during shutdown, and logs and retries Redis errors rather than stopping. The caller supplies the client, so TLS, ACLs, and persistence stay outside the package. `serve` runs two consumers: the gateway's events, and the outbox stream for `notifications`.
- `pkg/optional` — `optional.Of(v)` returns nil for the zero value (such as `""`) and a pointer otherwise, for optional fields, nullable columns, and generated API clients; `optional.OfPtr(p)` does the same for a value that may be missing, returning a copy so a domain object never shares memory with its props. Use them instead of a package-local helper; for a pointer to any value, use the builtin `new(v)`.
- `pkg/email` — `email.Valid(s)` is the one rule for an email address (bare `ada@example.com`, no display name, at most `email.MaxLength` = 320 characters, so address columns are `VARCHAR(320)`). IAM and delivery both use it; don't write another.
- `pkg/aggregate` — `Root` and `Events`: domain objects generate their IDs there and record the events their methods raise, which a service pulls after saving.
- `go mod tidy` fails in an app module that imports `pkg/` (it ignores `go.work` and tries to download the unpublished module), so adjust that app's `go.mod` by hand.
