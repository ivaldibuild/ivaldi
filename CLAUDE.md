## Current state of the repository

The repo is an early scaffold. Most of the layout is reserved but empty, so don't assume code exists because a directory does:

- Three binaries ([ADR 0010](docs/adr/0010-one-binary-for-the-components.md), [ADR 0013](docs/adr/0013-one-agent-per-runtime.md)): `apps/control-plane` builds `ivaldi`, whose subcommands `serve`, `gateway`, `worker`, and `indexer` start each component (only `serve` does anything yet: it validates the config, opens the database, runs IAM bootstrap, and serves the API and the authorization server; `cmd/server/wire.go` is the composition root); `apps/cli` builds `ivaldictl` (`auth login`/`status`/`logout`: browser sign-in as the `ivaldictl` OAuth client with a loopback redirect and PKCE, sessions kept in `credentials.json` and refreshed; or a service account's API token from `--api-token`/`IVALDI_API_TOKEN`, the only way in CI, where it never opens a browser; `release create`/`publish`/`withdraw`/`get`/`list`, reading the commit, ref, and run from GitHub Actions or GitLab CI; `service-account create`/`list`/`get`/`suspend`/`reactivate` (alias `sa`) and `api-token create`/`list`/`revoke`, whose `create` prints the secret once; commands take an `app.App` so tests inject the environment, clock, HTTP, and store; see `docs/self-hosting/ci-releases.md`); `apps/k8s-agent` builds `ivaldi-k8s-agent`, the Kubernetes agent (design: `docs/design/k8s-agent.md`; plan: `plans/issue-52-clusters-and-k8s-agent.md`, Phase B). So far it enrols, holds the Lease, tracks its Targets, and heartbeats, but does not deploy or observe yet: `internal/agent` (flags, each also read from `IVALDI_<FLAG>`; the `coordination.k8s.io` Lease; `/healthz` and `/readyz` on `:8080`; the run loop, which without a credential waits not-ready for a new enrolment token instead of exiting), `internal/auth` (redeems the token from the enrolment Secret, authenticates requests by projected token, bearer, or mTLS, renews at half life ±5%, and forgets a credential the control plane refuses), `internal/state` (the state Secret), `internal/targets` (fetches `GET /v1/agent/targets`, checks RBAC per namespace with `SelfSubjectRulesReview`, and runs one informer set per readable Target namespace; the heartbeat and refresh loops run in `internal/agent/serve.go` at the intervals the control plane sends), and `internal/apiclient` (generated, filtered to the agent's operations, plus a hand-written `ControlPlane` wrapper whose `StatusError` matches `ErrNotClusterAgent` on 403 and `ErrInvalid` on 422). It imports nothing from `pkg/` yet, so `go mod tidy` works in its module. This version targets Kubernetes only: another runtime, such as a VPS host, gets its own agent binary, not a provider in this one (ADR 0013); the domain (`Target.runtime`, `locator`, `pkg/release`, enrolment) stays runtime-neutral. In `ivaldi`, a component's command is `cmd/<component>` and its code `internal/<component>`. `internal/boundaries` tests the import rules: a component imports only its own packages and `pkg/`, and the control plane (`cmd/server` and every other `internal` package) imports no component. Add a new component to `boundaries.Components`. The root `--config` flag has no default, so the binary never needs a home directory.
- Implemented shared code in `pkg/` is `env`, `logging`, `homedir`, `database`, `transaction`, `pagination`, `id`, `identity`, `authorization`, `clock`, `slug`, `optional`, `email`, `release` (versions, version ranges, Channel rule configs and matching Releases against them, and Release status transitions), `aggregate`, and `events` (envelopes, the handler `Router`, the `Publisher` and `Consumer` interfaces, and Redis Streams publisher and consumer implementations in `events/redisstream`). `pkg/graph`, `orchestration`, `policy`, and `vcs` are empty placeholders for the capability boundaries in `docs/vision.md`.
- The control plane has migrations for eight capabilities: `outbox`, `audit`, `iam`, `team`, `policy`, `workspace`, `versioncontrol`, and `delivery` (each in `apps/control-plane/internal/<capability>/migrations`, with designs in `docs/design/`). Nothing applies them at startup yet. `outbox` is the transactional event log (ADR 0011): `internal/outbox` holds the `Recorder`, the relay, and a `postgres` repository; `delivery` writes its domain events through it in the transaction that changes the object. `serve` runs the relay beside the API (`wireOutbox`), forwarding events to the Redis stream `outbox.stream` (default `ivaldi:control-plane:events`); a publish that fails with `events.ErrUnavailable` leaves the batch leased and counts no attempt, so a Redis outage never dead-letters events.
- `iam` has its domain objects, following `delivery`'s conventions, plus sign-in and token issuance (ADR 0003, ADR 0012): PostgreSQL repositories in `iam/postgres`; `onboarding` (creates Organizations with their resource and owner grant), `bootstrap` (applies the config at start under an advisory lock), `signin` (`iam.Authentication`: passwords, Organization identity providers, platform providers), `oauthserver` (`iam.AuthorizationServer`: code + PKCE, rotating refresh tokens), `token` (signing keys from config, JWT issuer, JWKS), `connector` (Google, GitHub, OIDC behind one interface), and `authhttp` (the OAuth endpoints, provider redirects, and well-known documents beside `/v1`, plus the `/v1/auth/*` JSON operations the separate frontend's sign-in screens call; the control plane serves no HTML, see `docs/design/sign-in-flow.md`), `organizations` (`GET`/`PATCH /v1/organization`: the caller's Organization, read by any member and changed by owners and admins, authorized on its root resource and audited), `people` (`GET /v1/people`: the Organization's users with emails, last sign-in, and Organization roles, for any member; `iam.PeopleRepository`), `principals` (`GET /v1/principals?ids=`: names any of the Organization's principals by ID, whatever its kind, for any member; an Agent also names its Teams, archived ones with their `archived_at`, through `iam.PrincipalTeamSource` (`team.NewPrincipalTeamSource`); `iam.PrincipalReader`), `grants` (`GET`/`POST /v1/grants`, `DELETE /v1/grants/{id}`: grants on a resource and its ancestors via `iam.ResourceRepository`; `grant.manage` on the resource, `owner.manage` for the owner role; role scopes from `role.go`; the last active owner cannot be removed, checked with the Organization row locked; a grant to a Team goes to its group through `iam.TeamGroupSource`, which `team.NewGroupSource` implements by syncing the group first), `serviceaccounts` (`/v1/service-accounts` and their API tokens, `ivt_`-prefixed, of which only the SHA-256 hash and a 12-character prefix are kept; `service_account.read`/`.manage` on the Organization), `apitokens` (an `identity.Verifier` that checks API tokens against the database, acting as their active owner, and passes every other bearer token to the access-token verifier, so the API middleware and authorizer treat both alike), and `profile` (`GET /v1/me`: the caller's principal, Organization, and roles on it, for any signed-in caller; it refuses one that is no longer active). `pkg/identity` verifies access tokens offline, and `internal/api` authenticates operations that declare `Security`; `api.New` refuses any `/v1` operation that declares neither `Security` nor `Metadata: {api.Public: true}`. Each package exports interfaces and `New…` constructors and keeps its implementation unexported. Users, ServiceAccounts, AgentSessions, and Workloads embed a shared `principal` and share the `prn` prefix; records keyed by something other than an ID (`OrganizationDomain`, `PasswordCredential`, `GroupMember`, `OAuthAuthorizationCode`, `SigningKey`) have no `Prefix()`. Built-in roles and where each may be granted are in `role.go`; what each holds is in `permission.go`, by rule rather than by list (owner everything; admin everything but the owner-only permissions; member reads plus Work Item and Session permissions; viewer reads; a read permission is one ending in `.read`), so a capability's new permission needs no IAM change. Custom roles hold nothing yet. `iam/authorizer` implements `authorization.Authorizer` from grants (via `iam.AccessRepository`, one recursive query in `iam/postgres`): grants on a resource or its ancestors, directly or through groups, unexpired, and not on an archived resource. It is IAM's half of ADR 0003's single authorizer; with no policy yet, it denies agent Sessions, the system actor, and any request carrying an `ApprovalID`. Decisions get `dcn_` IDs that audit records carry. Agents (ADR 0007) are the `agent` principal kind (`iam.Agent`, table `iam.agents`), created only through a Team (`POST /teams/{id}/agents` or `POST /v1/agents`), and an Agent's last active Team cannot drop it; Agent Sessions do not run as Agents yet. `orchestration` owns Agent configuration (`orchestration.agent_configs`, so far the system prompt) and serves `/v1/agents` through `orchestration/agents`; identity stays in IAM and Team ownership stays in `team`. `iam.TeamGroups` keeps one IAM group (`source = 'team'`, `external_id` = the Team ID) mirroring each Team's members so grants can target Teams; an archived Team's group has no members, so its grants stop applying.
- `team`, `policy`, `workspace`, `delivery`, and `orchestration` have Go code, all built the same way (described under the `delivery` conventions below); `delivery` covers its configuration side (Environments, Targets, Lifecycles, Registries, Applications with artifacts, Channels, and placements) and Builds and Releases (`delivery/releases`: a Release is created from Builds named by digest, recording them inline as CI reports them, joins the one Channel whose rules it meets when none is named, and can be published in the same call; `release.manage` and `release.publish` on the Application's Project; tags wait on a registry client behind `delivery.TagResolver`) and Deployments (`delivery/deployments`: request, list, get, cancel, Target-agent assignments and reports, and the placement's current Deployment and Release). Each capability keeps its domain types and the interfaces it needs (`interfaces.go`: its repositories, its service interfaces, and hooks such as workspace's `Dependent` and `LockSource`) in its top-level package, each service in a sub-package with its HTTP API (`workspace/workspaces`, `projects`, `settings`; `team/teams`; `delivery/environments`, …), and its GORM repositories in `<capability>/postgres`. Contracts shared by several capabilities live with their owner: `identity.Actor` (`pkg/identity`) and the single authorizer (`pkg/authorization`: `Request`, `Decision`, `Require`, `WithDecision`, and its errors) in `pkg/` because the gateway and workers use them too; `iam.ResourceRegistrar`, `iam.OrganizationProvisioner`, and the IAM resource types, `audit.Recorder`, and `team.Directory` and `team.Owner` in `internal/iam`, `internal/audit`, and `internal/team` because only control-plane capabilities use them. `team.Owner` is the hook every capability that records an owning Team implements (`workspace.NewTeamOwnership`, `delivery.NewTeamOwnership`), so a Team that still owns active work cannot be archived. The authorizer is `iam/authorizer`, the audit recorder `audit/postgres` (insert-only `audit.records`, written in the change's transaction; only the system actor may have no principal), and `team.Directory` is `team.NewDirectory`. Other capabilities read each other without authorizing through small lookups: `workspace.NewLookups`, `workspace.NewSettingResolver`, `team.NewDirectory`. Each capability keeps its own defaults, limits, permission names, authorizer action names (`Action…`), audit event types, and aggregate types in its `constants.go`; enum types such as delivery's `Tier` live next to the domain type that uses them. Settings are defined by the capability that owns them in one shared `workspace.Definitions` registry (so far only `delivery.default_lifecycle`, registered by `delivery.RegisterSettings`, which Applications fall back to when created without a Lifecycle); a definition's `Validate` refuses a value with an error matching `workspace.ErrInvalid`, and any other error is treated as unexpected. `policy` holds only setting locks so far (no policy engine; `pkg/policy` stays empty): `policy/locks` serves `/setting-locks`, and `policy.NewLockSource` implements `workspace.LockSource`, which settings resolution and changes both obey. `cmd/server` (`wire.go`, `wire_policy.go`, `wire_delivery.go`, `wire_workspace.go`) wires all of it: the authorizer, the audit recorder, `workspace.NewProvisioner` (onboarding calls it to create each new Organization's default Workspace in the same transaction), the shared setting registry, locks, and resolver, Teams (with workspace and delivery as owners, and IAM for principals, Agents, and team groups), the workspace services (with `delivery.NewDependents` guarding archives), and delivery's services. Domain objects are the only surface that mutates domain state: their fields are unexported, they are created with `New…` constructors that apply creation rules, and they change only through their methods (`Update`, `Archive`, `MakeDefault`, `TransferTo`, `Change`, …). No method takes a time: domain objects and audit records read `pkg/clock`, which returns UTC truncated to microseconds so objects compare equal after a database round trip; tests fix it with `clock.Fix(t, …)` and so must not run in parallel. Services orchestrate (load, call methods, persist, record events and audit) and never set state themselves. Repositories only persist and retrieve. Audit records carry `Snapshot()` values. Value objects such as `Scope` and `Resolved` keep exported fields. IDs are ULIDs from `pkg/id`, generated by `pkg/aggregate` (see Identity below). A domain type that declares `Prefix()` (such as `Workspace` → `wsp`) gets prefixed IDs and registers the prefix with `id.MustRegister` in its package's `init` (a prefix claimed twice panics at startup); a type without `Prefix()` gets a plain ULID. GORM entities have no ID hooks. Database access goes through `pkg/database` (see Shared packages).
- The conventions every capability now follows, set by `delivery` (new capabilities follow them too):
  - **State and rebuilding** (`workspace` follows this too). Domain types expose `Snapshot()` (not `Data()`). There is no `Reconstitute…`: repositories rebuild stored objects with the same `NewX(props, &id)` constructor, passing the stored ID and timestamps in `NewXProps` (a new object leaves them nil). Creation rules therefore also run on load, so a rule added later must still accept existing rows. Child records owned by an aggregate (Lifecycle phases, Channel rules) are passed in the props and change only through the parent's methods; readers get them as snapshots.
  - **Identity.** Domain types never generate their IDs. Aggregates embed `aggregate.Root` and child records embed `aggregate.Entity` (`pkg/aggregate`), built in the constructor by the capability's `newRoot`/`newEntity(X{}.Prefix(), storedID)`, which generate a new ID or check a stored one and turn a bad one into an invalid-input error. `ID()` comes from the embedded type. `iam` and `workspace` follow this too.
  - **Events** (`iam` and `workspace` follow this too). Domain methods record events with `RecordEvent`, only when something actually changes (`set`/`anyTrue` helpers), and constructors record `<Type>Created` only when `IsNew()`. Types keyed by something other than their own ID embed `aggregate.Events` and count as new when their props carry no stored `CreatedAt`. Events live in `<type>_events.go`: value types named `<Type><PastTense>`, named `<capability>.v1.<aggregate>.<event>`, carrying the typed snapshot after the change plus a `previous_…` field only where a reassignment loses information. Snapshots have snake_case JSON tags and are the events' contract (`TestSnapshotJSONKeys` fixes their keys); hashes and other credential material are tagged `json:"-"`. Usage and contact tracking (agent reports, last-used times) records no event. IAM's shared `principal` methods record `iam.v1.principal.*` events with `PrincipalSnapshot`. Delivery writes its events to the outbox in the same transaction (see ADR 0011); `run` does it after saving and every create does it before the transaction ends. `serve`'s relay publishes them to Redis; nothing consumes that stream yet.
  - **Repositories save whole objects.** `UpdateX(ctx, x)` writes what `x.Snapshot()` holds; archive and restore are domain methods the service calls before saving. Every read takes the Organization ID; slug lookups also take their scope and match only active rows. Mappers (`*_mapper.go`, one struct per aggregate) convert between entities and domain types.
  - **Shared helpers.** The clock is `pkg/clock` (`clock.Now()`, `clock.Fix(t, …)` in tests, `clock.CopyTime`), and slugs come from `pkg/slug` (`Create`, `Validate`). Validation errors are `NewErrInvalidInput(msg)`, which matches the `ErrInvalid` sentinel.
  - **Lists page by cursor.** List queries have a `Page pagination.Query` field, and repositories return `*pagination.Result[*T]` (`pkg/pagination`), implemented with `database.Paginate` (see Shared packages). A capability's `postgres` package declares a `database.Keyset` per list and translates `pagination.ErrInvalidQuery` into its own invalid-input error (`delivery/postgres/keysets.go`).
  - **Services.** Each capability declares service interfaces (`EnvironmentService`, …) in `interfaces.go`. Domain types stay in the capability's top-level package; each service interface is implemented by a sub-package (`delivery/environments`, `registries`, `lifecycles`, `applications`) that also holds its HTTP API (`http_api.go`, `http_requests.go`, `http_responses.go`, error mapping in `errors.go`). The sub-package's `New…Service(opts...)` returns its unexported service wrapped in `authorized` (`authorization.go`), which implements the same interface: each method asks the authorizer about the right IAM resource, then passes the decision down with `authorization.WithDecision` (per object ID for batch operations, `""` for the whole call). The service underneath does no authorization; it writes through `internal/change` (`change.Run` for load-apply-save, `Writer.Events`, `Writer.AuditRecord`), whose audit write fails with `change.ErrUnauthorized` when the context carries no decision, so a service wired without its wrapper cannot change anything. Where a service needs one count or lookup from another area's repository, it declares a one-method interface (`LifecycleUsage`, `ChannelUsage`, `TargetLookup`, …) rather than taking the whole repository. `delivery.NewDependents` implements `workspace.Dependent` from the repositories, and `delivery.ActiveWorkspace`/`ActiveProject` check the Workspaces lookup. `delivery/routes_test.go` mounts every controller together to check operation IDs are unique and every operation needs a token.
- `Makefile` wraps golang-migrate's `migrate` CLI (`make help`): `<capability>_migration_generate name=<name>` creates a numbered pair, and `migrate_up`, `migrate_down capability=<c>`, and `migrate_version` take `DATABASE_URL`. Every capability numbers from 000001, so each must use its own version table (`<capability>_schema_migrations`, with `version_control` for `versioncontrol`); the Makefile sets it, so don't call `migrate` against the database without `x-migrations-table`. `deploy/helm` has charts for `ivaldi` and `ivaldi-agent` (both still close to the `helm create` scaffold). `migrations/`, `schemas/`, `scripts/`, and `.github/actions/` have no tracked files yet.

```sh
# Single CLI test
go test ./apps/cli/... -run TestName

# Tests against PostgreSQL (pkg/database and capability repositories); they skip

# makes and drops its own (pkg/database/databasetest).
IVALDI_TEST_DATABASE_URL='postgres://user:pass@localhost:5432/postgres?sslmode=disable' \

IVALDI_TEST_REDIS_URL='redis://localhost:6379/0' go test ./pkg/events/redisstream/

gofmt -l .        # list unformatted files

# Everything in containers (docker-compose.yml): PostgreSQL, Valkey, the migrations,
# the control plane on :8660, and the web app on :8670. The containerized control
# plane reads config.local.yml like `make local_serve`, overriding only the database
# and Valkey addresses. `make local` starts only PostgreSQL and Valkey, for
# `make local_serve`. All three create config.local.yml from config.local.example.yml
# when it is missing.
make local_stack

# The API's description and the clients generated from it. Run after changing
# an operation, a request, or a response: it rewrites api/openapi.json (from
# `ivaldi openapi`), ivaldictl's Go client (apps/cli/internal/apiclient, by
# oapi-codegen, a `tool` of the CLI module), and the web app's types
# (apps/webui/src/app/api/schema.gen.ts, by openapi-typescript).
make openapi
make openapi_check   # fails if a committed copy is out of date
```

`cmd/server`'s `TestTheCommittedOpenAPIIsCurrent` fails while `api/openapi.json` is stale. The description is built from `services.routes` in `cmd/server/routes.go`, the same list `serve` serves, so a new controller is added there (and its service set in the wiring) and never registered elsewhere. ivaldictl generates only the operations listed in `apps/cli/internal/apiclient/oapi-codegen.yaml`; add an operation ID there when a command starts calling it. The web app's `api/models.ts` names generated types rather than declaring its own. Two rules keep the generated types honest: a list in a response is never null (huma's `DefaultArrayNullable` is off, and `api`'s `emptyLists` transformer turns any nil slice into `[]`), and a snapshot field whose Go type has fixed values carries an `enum` tag listing them, pinned to the domain's constants by an `enums_test.go`.

There is no lint config or lint target yet; `go vet` and `gofmt` are the checks.

## Module layout gotchas

- Every app and `pkg/` is a separate Go module. Root `go.work` stitches together `pkg` and every app, including `apps/cli`, so apps import shared code as `github.com/ivaldibuild/ivaldi/pkg/...` without `replace` directives. Builds that run with `GOWORK=off` (for example, a per-module Docker build) lose that and would need a `replace` or a published `pkg` version.
- Module paths: `pkg` is `github.com/ivaldibuild/ivaldi/pkg`, while each app (including the CLI) is its own `github.com/ivaldibuild/ivaldi-<app>` module. `apps/control-plane`'s module, `ivaldi-control-plane`, also holds the gateway, worker, and indexer.
- `VERSION` in each binary's `cmd` package is a `var` so `-ldflags "-X main.VERSION=…"` can set it; the Makefile does.
- `pkg/env` and `pkg/logging` were ported from another project; leftover fixture names (e.g. `dispatch` in `env_test.go`) are test data only.

## Shared packages

- `pkg/env` — struct-tag config loader. Layering is `envDefault` < YAML < environment variables; errors are aggregated (`*env.AggregateError`) rather than returned on first failure. Use `Options.Source` to inject env lookups in tests instead of `os.Setenv`. `LoadDotEnv` loads `.env` files.
- `pkg/logging` — backend-agnostic `Logger` interface with a zap implementation, lumberjack file rotation, and a testify `MockLogger`. Depend on the `Logger` interface, not zap.
- `pkg/database` — opens PostgreSQL with GORM and carries one transaction in the context: `Transactor.WithinTx` starts it (or joins one already in the context), and repositories call `database.Conn(ctx, db)` so their writes join it. A transaction only spans repositories sharing one `*gorm.DB`, so open it once per process. `UniqueViolation`/`ForeignKeyViolation`/`CheckViolation` return the constraint name for translating into domain errors. `TextArray` maps a `TEXT[]` column in a GORM entity. `databasetest.New(t, migrations.FS)` gives tests a throwaway database. Never use GORM `AutoMigrate`; migrations own the schema.
- `pkg/pagination` — `Query` and `Result[T]` for paged lists, with no database code so domain packages and service interfaces can use them (like `pkg/transaction`). `pkg/database`'s `Paginate` implements keyset paging with them: a capability gives it a fresh base query per call and a `Keyset` (the allowlist of sort columns, a default, and the tie-breaking ID column), and gets back a `Page` of rows plus opaque cursors; `ToResult` maps the rows to domain objects. Invalid sorts and cursors fail with `pagination.ErrInvalidQuery` before any query runs.
- `pkg/transaction` — the `Transactor` interface (`WithinTx`) that capabilities depend on to make writes commit together, with no database code, so domain packages can import it. `database.Transactor` implements it. Capabilities use this one rather than declaring their own. The guarantee only holds if every write inside `WithinTx`, including other capabilities' implementations called there, goes through the context it passes.
- `pkg/id` — ULID primary keys, generated through `pkg/aggregate`'s `NewRoot`/`NewEntity`, prefixed for types that declare `Prefix()`. Prefix registration (`id.MustRegister`) catches duplicates only within one program, not across deployables.
- `pkg/events` — `Envelope`, `Wrap`/`Decode`, the handler `Router`, and the `Publisher` and `Consumer` interfaces. `pkg/events/redisstream` implements `Publisher` and `Consumer` over Redis Streams. The publisher writes one flat entry per envelope with approximate `MAXLEN` trimming and wraps every Redis error in `events.ErrUnavailable` (a transport failure, not the event's); the consumer reads with a group, drains its own pending entries on startup, reclaims idle entries from stopped consumers, supports automatic or handler-driven acknowledgement, and dead-letters entries it gives up on (including ones whose handler panics or never finishes). It reads only as many entries as it has free handler slots, acknowledges a finished handler even during shutdown, and logs and retries Redis errors rather than stopping. The caller supplies the client, so TLS, ACLs, and persistence stay outside the package. No component starts a consumer yet.
- `pkg/optional` — `optional.Of(v)` returns nil for the zero value (such as `""`) and a pointer otherwise, for optional fields, nullable columns, and generated API clients; `optional.OfPtr(p)` does the same for a value that may be missing, returning a copy so a domain object never shares memory with its props. Use them instead of a package-local helper; for a pointer to any value, use the builtin `new(v)`.
- `pkg/email` — `email.Valid(s)` is the one rule for an email address (bare `ada@example.com`, no display name, at most `email.MaxLength` = 320 characters, so address columns are `VARCHAR(320)`). IAM and delivery both use it; don't write another.
- `pkg/aggregate` — `Root` and `Events`: domain objects generate their IDs there and record the events their methods raise, which a service pulls after saving.
- `go mod tidy` fails in an app module that imports `pkg/` (it ignores `go.work` and tries to download the unpublished module), so adjust that app's `go.mod` by hand.
